## How to Contribute

### Proposing a bundle

Open a pull request adding an entry to `registry.json`. To be accepted, a bundle needs:
- A public repository with a `bundle.json` at its root (see [docs/creating-a-bundle.md](https://github.com/AudricSan/Kintai/blob/main/docs/creating-a-bundle.md) in the main Kintai repository).
- At least one tagged GitHub Release (`vX.Y.Z`, not draft, not prerelease) matching a version in `bundle.json`.

### Reporting issues

Open an issue describing the problem (a bad registry entry, a broken automation, an incorrect `README.md`/`registry.json` format example, etc.).

### Submitting a Pull Request

1. Fork the repository
2. Create a branch: `git checkout -b feat/my-feature` or `fix/my-bug`
3. Make your changes
4. Run the validation script: `node scripts/validate-registry.js`
5. Open a pull request against `main` — it's a protected branch (PR + passing CI required, no direct push)

## Code Conventions

- Comments in code are written in French; everything else (commit messages, PR descriptions, docs) in English
- `registry.json` is hand-edited or updated by automation (see below) — never generated by a build step
- `scripts/validate-registry.js` is the source of truth for the `registry.json` contract; keep it and `README.md` in sync if the format changes

## Automation

- `scripts/sync-versions.js`, run hourly by `.github/workflows/sync-versions.yml`, polls each bundle's `repository_url` for tagged GitHub Releases and opens a PR against `main` when a bundle's `versions` are out of date. It never pushes directly.
- `scripts/validate-registry.js`, run by `.github/workflows/tests.yml` (job `test`), is the required status check on every PR and push to `main`.

## Running the checks locally

```bash
node scripts/validate-registry.js
node scripts/sync-versions.js   # dry-runs against the live GitHub API, only writes registry.json if something changed
```

No dependencies to install — both scripts use Node's built-in `fetch` (Node 18+).
